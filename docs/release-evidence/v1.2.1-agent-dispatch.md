# Agent Dispatch v1.2.1 compatibility evidence

Probes ran 2026-11-10 UTC on Linux/amd64 from the release checkout at `release/v1.2.1` commit `75b7ee4f68739f47c0d622a267895c1e176aad00`. That commit merges `origin/main` at `ac54b7697b2dcf1d22a8721a2b58becf262fe95a` (#528) into the committed release preparation: the changelog, the upgrade, reference, and benchmark docs, and the 1.2.1 template ownership and migration manifests. One uncommitted changelog reference edit was also applied. The release head differs from `75b7ee4f` only in documentation: that `CHANGELOG.md` reference, the v1.2.1 row in `site/docs/upgrades.mdx`, and this evidence file. `git diff 75b7ee4f <release head> --stat` shows this; no Go source differs. Go's default VCS stamping embeds revision `75b7ee4f` and `vcs.modified=true` in the executable, so the SHA256 below belongs to that modified tree, and a build of a later commit has a different hash. The build used Go 1.27.3, and the development executable's SHA256 was `131d524772a17b40c5feabcad855ceadddba472e47286be8ddcc99bd977434cc`.

The remaining release preparation does not change the dispatch implementation, dependencies, or configured probe targets. The certified SHA and rehearsal run URL of the final release commit are recorded on the release pull request, because committing them here would change the certified commit.

This release changes Agent Dispatch in two ways:

- #523: pinned `agent-layer` MCP servers re-execute from a content-addressed image copy, and freshness records the start selection.
- #526: the pre-launch Muse recovery baseline read on `continue` has its own 30-second limit per attempt, retries once when the host hangs, and records host stderr in the run's `muse-baseline.stderr`.

Since v1.2.0, #523's MCP freshness change and #528's launch-fence and cancellation helpers also changed launch and pre-launch code shared by all providers; the baseline read itself runs only for Muse. The four passing providers exercised that shared path end to end. Antigravity also launched through it and returned its structured terminal result.

## Setup

All five declared dispatch providers are enabled and available locally. They were probed sequentially, one provider at a time. Each probe used the existing release checkout's `.agent-layer/config.toml`, `.agent-layer/.env`, normal local provider homes and sign-ins, configured models/efforts, and permissions. No configuration, credentials, or sign-in was changed.

The CLI was built with `make al-dev-build AL_DEV_BIN_DIR=<release scratch dir>`: the same build, written outside `.agent-layer/tmp/dev-bin` so the operator's running MCP server was not replaced. Source selection and environment setup otherwise followed `docs/RELEASE.md`, with `AL_DEV_EXECUTABLE` and `PATH` pointing at that build.

Each fresh prompt requested `release-probe-fresh`, and each continuation requested `release-probe-continue`, with no tools or file modifications. No probe was repeated. The Antigravity failure reported exhausted quota, which is not a temporary condition under `docs/RELEASE.md`.

An earlier probe round on `4118ff3a`, before #528, failed the Muse continuation with `read Muse recovery baseline before launch: read |0: file already closed` ([#526](https://github.com/conn-castle/agent-layer/issues/526)). #528 fixed that failure, and this record supersedes that round.

## Limitations and known issues

- Antigravity was not validated for this release because the local account quota is exhausted. It passed the same probes for v1.2.0 with CLI `1.5.3`; it now reports `1.5.5`. The fresh probe launched agy `1.5.5` through the release build, and Agent Layer parsed its structured terminal result, which supplied the quota reason. The success path and continuation on `1.5.5` are untested; a re-probe after the quota resets is tracked in [#531](https://github.com/conn-castle/agent-layer/issues/531).
- The intermittent Muse host hang behind #526 lies inside Muse and did not reproduce in more than 20 attempts. These probes show the fixed path succeeds. The hang-and-retry behavior is covered by the fake-host tests in `internal/agentdispatch/muse_recovery_baseline_test.go`.
- These short probes do not establish expired-credential refresh for Grok ([#421](https://github.com/conn-castle/agent-layer/issues/421)) or the cause of earlier unclassified shutdown failures ([#430](https://github.com/conn-castle/agent-layer/issues/430)).
- These probes do not exercise the #523 MCP image handoff. That handoff is covered by the real-image freshness tests, the launcher test that checks the pinned server runs under `images/`, and a manual check that a pinned `al dispatch mcp-server` ran from `images/<sha256>/al`.

Raw probe logs (`probe2-*.log`) and the options output are kept locally in `.agent-layer/tmp/release-v1.2.1/`. Invocation records live under `.agent-layer/tmp/runs/<invocation_id>/`. These are local evidence locators, not uploaded artifacts. The provider probes do not establish signing, notarization, hosted certification, or publication.

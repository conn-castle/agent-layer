<div className="features-section">
  <h2 className="features-title">Why Agent Layer?</h2>
  <p className="features-subtitle">Edit setup once in <code>.agent-layer/</code>. Agent Layer writes each client's config when you launch.</p>

  <div className="features-list">
    <div className="feature-item">
      <h3 className="feature-title">Single Source of Truth</h3>
      <p className="feature-description">Edit <code>.agent-layer/</code> once. Skills align with the <a href="https://agentskills.io/specification">agentskills.io specification</a>, and the <Link to="/best-practices">Best Practices guides</Link> help keep skills and instructions maintainable.</p>
    </div>

    <div className="feature-item">
      <h3 className="feature-title">Sync on Run</h3>
      <p className="feature-description">By default, <code>al &lt;client&gt;</code> regenerates client configs first, then launches the client. VS Code can skip sync with <code>--no-sync</code>.</p>
    </div>

    <div className="feature-item">
      <h3 className="feature-title">Consistent Approvals</h3>
      <p className="feature-description">Define safety rules once. Agent Layer projects them into each client that supports approvals.</p>
    </div>

    <div className="feature-item">
      <h3 className="feature-title">MCP Everywhere</h3>
      <p className="feature-description">Configure MCP servers in <code>.agent-layer/config.toml</code>. They appear in each client that supports them.</p>
    </div>

    <div className="feature-item">
      <h3 className="feature-title">Version Pinning</h3>
      <p className="feature-description">Pin the repo to a specific Agent Layer version so every machine runs the same release.</p>
    </div>

    <div className="feature-item">
      <h3 className="feature-title">Local & Fast</h3>
      <p className="feature-description">No telemetry. Network is used only for update checks, version downloads (pinning), and MCP servers you enable. See <a href="/security">Security</a> for details.</p>
    </div>
  </div>
</div>
